# Web chat

```bash
make agent-chat-ui        # http://127.0.0.1:8002
```

[`app/web.py`](https://github.com/orq-ai/orq-workshop/blob/main/app/web.py) puts the same `chat()` behind `POST /api/chat`, and [`web/index.html`](https://github.com/orq-ai/orq-workshop/blob/main/web/index.html) is the page: the transcript, the tools each answer called as chips, the model and seconds per answer, and a **trace** link per answer. **Try these** holds prompts that walk into each policy rule (window, limit, already refunded, out of scope, fake approvals, PII); a click sends one. The **Models / Agents** toggle chooses which list the dropdown shows. The model dropdown switches the model per turn, so you can replay the same prompt on `gpt-5.4-nano` and compare. After `make seed-workspace` it also lists `agent/<prefix>-refund-agent-hosted`: the same agent with its three tools as orq.ai code tools, so orq.ai runs the loop and the tools and your machine makes one call per turn (module 08 has the managed agent whose tools still run on your side). The browser sends the full history back every turn, as the rest of the repo does; each conversation gets its own in-memory order store, so a refund stays refunded until **New conversation** or a server restart. Set `ORQ_WORKSPACE` in `.env` to your workspace key (`active_workspace_key` in `orq doctor`) and the link opens that trace; unset, it opens Traces, where you search the trace id. Every turn is traced as `refund-chat`, with a `ws-chat-…` thread per conversation. A tool the policy refused shows as a `DECLINED` or `NOT FOUND` chip. The **Guardrails** dropdown picks `PII · input`, `Refund limit · output` or `Both`; each tags the request so one gateway rule (`<prefix>-guardrail-rule-chat-pii`, `-refund`, `-chat`, created by `make seed-workspace`, which needs an admin key) blocks personal data on input and/or refund promises over EUR 500 on output; a block shows as its own message with the guardrail and the reason, and the trace link. The rule matches on request metadata because request-level `guardrails` are ignored on Responses. Leave `ORQ_API_KEY` empty and the chat uses your `orq auth login` session instead (tokens last an hour; the link then opens the CLI's active workspace).
